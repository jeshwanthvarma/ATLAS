1. PROJECT INTRODUCTION

---

ATLAS is a web-based Unified Infrastructure Monitoring and Security Platform designed to provide centralized monitoring of Linux system resources and infrastructure information.

The system provides administrators with a web dashboard through which important system information such as CPU, memory, disk, network, uptime, and system details can be viewed.

ATLAS combines web development, Linux system administration, database management, authentication, monitoring, and security concepts into a single application.

The project is developed using Ubuntu 24.04 LTS through Windows Subsystem for Linux 2 (WSL2).

2. PROBLEM STATEMENT

---

Modern computer systems generate large amounts of infrastructure and system information. Administrators need to continuously monitor resources such as CPU, memory, disk space, network activity, services, and system health.

Without centralized monitoring, administrators may need to use multiple Linux commands or separate tools to understand the condition of a system.

This creates several challenges:

* System information is distributed across different commands and tools.
* Resource problems may not be immediately visible.
* Administrators need technical knowledge of multiple Linux utilities.
* Monitoring information may not be presented in an easy-to-understand graphical form.
* Authentication and monitoring functionality may exist as separate systems.
* Expanding a monitoring solution with security, alerts, reports, and automation can become complex.

ATLAS addresses this problem by providing a centralized web-based platform for infrastructure monitoring with an architecture that can also support security monitoring, alerts, reports, and automation.

3. PROPOSED SOLUTION

---

ATLAS provides a centralized monitoring application consisting of:

* Web-based user interface
* Secure user authentication
* Node.js/Express backend
* Linux system monitoring
* REST APIs
* PostgreSQL database
* Monitoring dashboard
* Modular backend architecture

The backend collects information from the Ubuntu system and exposes it through REST APIs.

The frontend communicates with these APIs and presents the information through the ATLAS dashboard.

Firebase Authentication is used for user authentication, while PostgreSQL stores application-specific user and system information.

9. BASIC SYSTEM WORKFLOW
------------------------

The basic ATLAS workflow is:

Step 1:
The user opens the ATLAS web application.

Step 2:
The user logs in using the authentication interface.

Step 3:
Firebase Authentication verifies the user's credentials.

Step 4:
The authenticated user is allowed to access the ATLAS application.

Step 5:
The frontend requests monitoring information from the Express.js backend.

Step 6:
The monitoring service collects system information from Ubuntu.

Step 7:
The backend returns monitoring information through REST APIs.

Step 8:
The frontend processes the returned information.

Step 9:
The information is displayed through the ATLAS dashboard.

11. PROJECT ARCHITECTURE
------------------------

ATLAS follows a layered and modular architecture.

The major layers are:

1. Presentation Layer
   Provides the web-based user interface.

2. Authentication Layer
   Handles user identity and authentication using Firebase.

3. Application Layer
   Contains the Node.js and Express.js backend.

4. Monitoring Layer
   Collects infrastructure information from Ubuntu.

5. Database Layer
   Stores structured application information using PostgreSQL.

6. System Layer
   Provides access to operating-system resources and monitoring information.
